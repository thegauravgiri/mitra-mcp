If your client supports the MCP authorization spec (OAuth 2.1), it discovers sign-in automatically from this URL — sign in with the same Google account you used here, and no keys need to go into your client config at all:

Example configuration, for clients that take a raw JSON server entry (e.g. Claude Desktop's claude_desktop_config.json):

{
  "mcpServers": {
    "mitra": {
      "url": "{{ mcp_url }}"
    }
  }
}

Client doesn't support OAuth yet? You can still fall back to the legacy per-service headers instead of signing in — but then your API keys live in the client config again, which is exactly what this vault replaces. Prefer the OAuth path above whenever your client supports it.
